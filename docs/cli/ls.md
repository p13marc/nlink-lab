# `nlink-lab ls`

The labs on this host: name, node count, when it was deployed, and the
file it came from. `*` marks your current lab (`nlink-lab use`). Reading
the state needs root or the `nlink-lab` group.

```bash
nlink-lab ls
nlink-lab ls --scan        # also orphans and stale labs
nlink-lab -q ls            # names only, for scripts
```

`--scan` walks the host for lab resources without a state file (mgmt
bridges, veths, tagged namespaces a crashed deploy left) and for labs
whose namespaces are gone (a reboot). `nlink-lab destroy --orphans`
reaps the first kind, `nlink-lab destroy LAB` the second.

Labs deployed by a version older than 0.14 live in a per-user state
directory; `ls` lists them under a note, and `sudo nlink-lab doctor
--fix` moves the idle ones.
