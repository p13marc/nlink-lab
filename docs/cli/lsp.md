# `nlink-lab lsp`

A Language Server Protocol server for NLL, over stdio. Editors run
`nlink-lab lsp` and get the checks that `validate` and `lint` already
perform, positioned in the file rather than printed as paths.

Client configuration for VS Code, Neovim, Helix, Emacs and Zed lives in
[`editors/README.md`](../../editors/README.md).

## What it provides

| Request | Behaviour |
|---------|-----------|
| `textDocument/publishDiagnostics` | Lex and parse errors at their exact token, every [validator](validate.md) error and warning, and every [lint](lint.md) finding as a hint. `code` is the rule id, `source` is `nlink-lab`. |
| `textDocument/documentSymbol` | `lab`, `node`, `profile`, `network`, `pool`, `site`, `let` and `param` declarations. |
| `textDocument/definition` | `node:iface` endpoints and `: profile` references jump to their declaration; `${node.iface}` cross-references and network members resolve too; an `import` string opens the module. |
| `textDocument/hover` | A node shows its profiles, image and resolved addresses per interface; a profile shows which nodes use it; a keyword shows its syntax. |
| `textDocument/completion` | Statement keywords at the start of a line, block properties inside a block, interface names after `node:`, and `${var}` for `let`/`param` names. |
| `textDocument/formatting` | The same token-level formatter as [`fmt`](fmt.md), so the editor and the `fmt --check` CI gate cannot disagree. |

## How it resolves imports

`import` statements resolve against the **document's own directory**, and
imported modules are read from disk. That means an unsaved buffer is checked
exactly like a saved file — but an unsaved edit to an imported *module* is not
visible to files that import it until you save it.

An error inside an imported module is reported on the `import` statement that
pulled it in, with the module's own path, line and column in the message.

## Positions that cannot be exact

The validator reports issues against the **lowered** topology, so its locations
are data-model paths (`links[3].addresses[1]`, `networks.core.subnet`) rather
than source offsets. The server maps them back onto the file: a declaration's
name where it can, the enclosing statement otherwise.

Some entities have no source span at all — a node from
`for i in 1..4 { node spine${i} }`, a link generated by `mesh`/`ring`/`star`, a
name prefixed by `site` or by an `import` alias. Those diagnostics are reported
at the top of the file with the data-model path appended to the message, so
nothing is silently dropped.

## Notes

- stdout carries only JSON-RPC; logs go to stderr, including under `-v`.
- Positions are UTF-16 code units, the LSP default.
- Full-document sync: a re-analysis is microseconds on real topologies.
- `--stdio` is accepted and ignored, for clients that always pass it.
