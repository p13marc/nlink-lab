# `nlink-lab top`

A live terminal UI over a running lab: nodes, the selected node's
interfaces, and its TCP flows, refreshed every `--interval`. It is
[`diagnose`](diagnose.md) + [`impair`](impair.md) in one screen, and
`--once --json` prints one metrics snapshot (what `metrics` did).

```bash
sudo nlink-lab top -L mylab            # collect itself (root)
sudo nlink-lab top -L mylab --interval 2s
nlink-lab top -L mylab                 # without root: read the daemon's
nlink-lab top -L mylab --once          # one text frame, for pipes and CI
```

## Panes

| Pane | Columns |
|------|---------|
| Nodes | name, kind (`ns`/`container`), interface count, summed rx/tx, issue count |
| Interfaces | name, state, rx/tx, packets/s, errors, drops (`N/M tc` when tc is dropping), and the **effective impairment** with its origin — `topology`, `live` or `partitioned` |
| Flows | process, pid, local and remote address, tx/rx goodput, retransmit ratio |

Flow rates need two samples (they are a delta), so the Flows pane says
`collecting` on the first one, and container nodes never report flows.

## Keys

| Key | Action |
|-----|--------|
| `↑` `↓` / `k` `j` | move within the focused pane |
| `Tab` / `Shift-Tab` | next / previous pane |
| `s` | cycle sort: name, traffic, issues |
| `/` | filter nodes and interfaces by substring |
| `i` | impair the selected interface |
| `c` | clear its impairment |
| `p` / `h` | partition / heal it |
| `?` | key help |
| `q`, `Esc`, `Ctrl-C` | quit |

The `i` prompt takes `KEY VALUE` pairs (`KEY=VALUE` also works) using the
same property names as [`impair`](impair.md) and NLL: `delay`,
`jitter`, `loss`, `rate`, `corrupt`, `reorder`, `duplicate`,
`delay-correlation`, `loss-correlation`, `limit`.

```
delay 50ms loss 1%
delay=50ms rate=10mbit
```

Values are passed through verbatim, exactly as `impair` does, but
obvious mistakes (`delay 50` with no unit, `loss 150%`, a duplicate key)
are rejected in the prompt so they can be corrected in place. Writes go
through the same `RunningLab` calls as `impair`, so they are persisted in
the lab state and survive an `apply`; impairing a partitioned endpoint
records the value for `heal` rather than lifting the partition.

## Two sources

**Local** (as root) collects the snapshots itself, with the collector
the daemon uses: it calls `diagnose` in every namespace, which needs
root. Every key works.

**The daemon** (without root, with `--daemon`, or with
`NLINK_LAB_DAEMON` set) subscribes to the lab's metrics on
`nlink-labd`, the host daemon: its socket
`/run/nlink-lab/api/api.sock`, or the endpoint `NLINK_LAB_DAEMON`
names (`ssh://HOST` reaches another host's daemon over ssh). It needs
the `nlink-lab-viewer` group, or `nlink-lab`, not root. The impairment
column is the daemon's. A member of `nlink-lab` (an operator) changes
impairments through the daemon with `i`/`c`/`p`/`h`; for a viewer they
are disabled and say so. Without root and without a daemon, `top` says
how to get either.

## `--once`

Prints a single frame as plain text and exits, touching no terminal
control sequences — safe in pipes, in CI and under `watch -n1`. With
`--json` it prints the raw metrics snapshot
([schema](../json-schemas/metrics-snapshot.schema.json)), which is what
`metrics` printed. The interactive view refuses to start
without a terminal and tells you to use `--once`.

Live terminal UI for a running lab (nodes, interfaces, flows).

As root, collects a metrics snapshot every `--interval` itself, like `diagnose`. Without root (or with `--daemon`, or `NLINK_LAB_DAEMON` set) it reads them from the nlink-lab daemon, `nlink-labd`: no root needed. The write keys then need the `nlink-lab` group (an operator); a viewer only watches.
