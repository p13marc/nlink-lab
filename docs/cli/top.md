# `nlink-lab top`

A live terminal UI over a running lab: nodes, the selected node's
interfaces, and its TCP flows, refreshed every `--interval` seconds. It is
[`diagnose`](diagnose.md) + [`metrics`](metrics.md) + [`impair`](impair.md)
in one screen.

```bash
sudo nlink-lab top mylab               # collect locally (needs root)
sudo nlink-lab top mylab --interval 2
nlink-lab top mylab --zenoh            # read a running `daemon` (no root)
nlink-lab top mylab --once             # one text frame, for pipes and CI
```

## Panes

| Pane | Columns |
|------|---------|
| Nodes | name, kind (`ns`/`container`), interface count, summed rx/tx, issue count |
| Interfaces | name, state, rx/tx, packets/s, errors, drops (`N/M tc` when tc is dropping), and the **effective impairment** with its origin — `topology`, `live` or `partitioned` |
| Flows | process, pid, local and remote address, tx/rx goodput, retransmit ratio |

Flow rates need two samples (they are a delta), so the Flows pane says
`collecting` on the first one, and container nodes never report flows.

## Keys

| Key | Action |
|-----|--------|
| `↑` `↓` / `k` `j` | move within the focused pane |
| `Tab` / `Shift-Tab` | next / previous pane |
| `s` | cycle sort: name, traffic, issues |
| `/` | filter nodes and interfaces by substring |
| `i` | impair the selected interface |
| `c` | clear its impairment |
| `p` / `h` | partition / heal it |
| `?` | key help |
| `q`, `Esc`, `Ctrl-C` | quit |

The `i` prompt takes `KEY VALUE` pairs (`KEY=VALUE` also works) using the
same property names as [`edit --set-impair`](edit.md) and NLL: `delay`,
`jitter`, `loss`, `rate`, `corrupt`, `reorder`, `duplicate`,
`delay-correlation`, `loss-correlation`, `limit`.

```
delay 50ms loss 1%
delay=50ms rate=10mbit
```

Values are passed through verbatim, exactly as `impair --delay` does, but
obvious mistakes (`delay 50` with no unit, `loss 150%`, a duplicate key)
are rejected in the prompt so they can be corrected in place. Writes go
through the same `RunningLab` calls as `impair`, so they are persisted in
the lab state and survive an `apply`; impairing a partitioned endpoint
records the value for `heal` rather than lifting the partition.

## Two sources

**Local (default)** collects with the same collector `daemon` uses, which
calls `diagnose` in every namespace and therefore **needs root** — there is
no partial snapshot to fall back to, so it fails immediately with a message
pointing at `sudo` or `--zenoh`.

**`--zenoh` / `--zenoh-connect ENDPOINT`** subscribes to a running
[`daemon`](daemon.md)'s metrics topic instead. No root, and no write
actions: there is no partition RPC and the impairment RPC carries only six
of the ten knobs, so `i`/`c`/`p`/`h` are disabled and say so. The
impairment column still works when the lab's state file is readable
locally.

## `--once`

Prints a single frame as plain text and exits, touching no terminal
control sequences — safe in pipes, in CI and under `watch -n1`. With
`--json` it prints the raw metrics snapshot
([schema](../json-schemas/metrics-snapshot.schema.json)), the same shape
`metrics --format json` emits. The interactive view refuses to start
without a terminal and tells you to use `--once`.
