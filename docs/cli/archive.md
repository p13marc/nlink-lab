# `nlink-lab archive`

Portable lab archives (`.nlz`, a tar.gz): a manifest, the topology
(`topology.nll`), its `--set` params, the rendered topology and SHA-256
checksums of every file. An archive is a repro to attach to a bug.

```bash
# from a topology file, or from a running lab
nlink-lab archive create wan.nll --set wan_delay=80ms -o wan-80ms.nlz
nlink-lab archive create -L wan --include-running-state

nlink-lab archive inspect wan-80ms.nlz        # manifest and counts, nothing extracted
nlink-lab archive extract wan-80ms.nlz --dir /tmp/wan
sudo nlink-lab deploy wan-80ms.nlz            # deploy it straight away
```

`extract` checks every checksum (a partial download or an edit in place
is refused), the format version, then validates the topology: the NLL
re-parsed with the archive's params, or with `--no-reparse` the
rendered topology (an archive made by a newer nlink-lab). `deploy
FILE.nlz` does the same, extracting into the lab's state directory, so
the files containers mount live as long as the lab.

Portable lab archives (`.nlz`): `create`, `extract`, `inspect`.

An archive holds a manifest, the topology, its params, the rendered topology and checksums: a repro to share. `nlink-lab deploy FILE.nlz` deploys one.

Usage: nlink-lab archive <COMMAND>

Commands:
  create   Write an archive of a topology file, or of a running lab (`-L`)
  extract  Check an archive's checksums and validate it, extracting it into a directory (default `./<lab>/`)
  inspect  Summarize an archive without extracting it
