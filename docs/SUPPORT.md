# Support tiers

nlink-lab is a wide surface for one maintainer: the library, the CLI,
the daemon and its API, a desktop app, a language server, three
editor grammars, and the subsystems behind them (firewall, FRR, Wi-Fi,
containers, scenarios, …). Not every part can promise the same. This
page says what each part promises, so you can tell what to build on.

## The tiers

| Tier | Promise |
|------|---------|
| **Core** | Breaks only with a CHANGELOG Migration note **and** a release in which the old form still works or says what replaced it. NLL: the old spelling keeps parsing for a release, with a deprecation warning once #334 brings them (and an autofix, `nlink-lab migrate`). CLI: a removed command or flag is a usage error (exit 64) that names its replacement (`removed.rs`). Library: `#[deprecated]` for a release, and semver. |
| **Supported** | Breaks only with a CHANGELOG Migration note. Tested in CI (the root lane included). |
| **Experimental** | May change or go in any minor release. CI may not test it (Wi-Fi's root tests skip on the runner). Marked as such: an experimental command in `nlink-lab --help`; the desktop app on its home screen and in its `--help`; Wi-Fi once in the log of a process that deploys it (the daemon's included). |

0.x minor releases (0.15 → 0.16) may break; patch releases do not.
Every break is in the CHANGELOG's `### Migration` section of its
release.

## Subsystems

| Tier | Parts |
|------|-------|
| **Core** | The NLL language; `deploy`, `apply`, `destroy`, `verify`; `exec`, `spawn` and the rest of running things in a node; `impair` and `--partition`; the library's stable layer (being curated, #331); `#[lab_test]`; the state layout (`/var/lib/nlink-lab`, schema-versioned) |
| **Supported** | Firewall, NAT and conntrack; FRR (OSPF, BGP); WireGuard, VRF, VXLAN, bonds, VLANs, macvlan/ipvlan; container nodes; `capture`; scenarios; benchmarks; snapshots and archives; `nlink-labd` and its API (unix socket, ssh `dial-stdio`, the Zenoh bridge); `top`; `lsp`, `fmt`, `lint`; the tree-sitter, VS Code and Zed grammars |
| **Experimental** | The desktop app (`nlink-lab-gui`); Wi-Fi emulation (it needs `mac80211_hwsim`, which the CI runner cannot load) |

## Moving between tiers

- A part moves **up** (experimental → supported → core) once it is
  tested in CI and its interface has held for a release. The move is a
  CHANGELOG line.
- A part moves **down** only in a release's notes, with the reason; a
  core part goes through supported first.

## Removal candidates

Reviewed in every release PR: anything that has gone unused for two
releases, or that duplicates a better path, is proposed for removal
there, with a Migration note when it goes.
