# `nlink-lab impair`

Change an endpoint's netem impairment while the lab runs. The
impairment is written like the NLL's — `delay 50ms jitter 5ms loss 1%
rate 10mbit` (or `delay=50ms,loss=1%`) — and replaces the endpoint's
whole impairment. It is kept in the lab's state, so `apply`, `verify`
and `snapshot` see it, and `status` marks it as set at runtime.

```bash
sudo nlink-lab impair r1:eth0 delay 50ms loss 1%           # what r1:eth0 sends
sudo nlink-lab impair r1:eth0 delay 200ms --dir in          # what it receives
sudo nlink-lab impair r1:eth0 loss gemodel 1% 30% 70% 0.1%  # a bursty loss model
sudo nlink-lab impair r1:eth0 --clear --dir both
sudo nlink-lab impair r1:eth0 --partition                   # drop everything; --heal ends it
sudo nlink-lab impair --pair a b delay 20ms                 # on a network, a → b only
nlink-lab impair --show
```

`--dir in` installs the impairment on the egress of the endpoint's link
peer, so it needs a point-to-point link; between members of a bridge
`network`, use `--pair SRC DST` (one HTB + netem tree per source
interface, with `--rate-cap` for an HTB ceiling).

`loss-correlation` is not bursty loss: it lowers a small loss rate
(`loss 0.5% loss-correlation 25%` drops almost nothing), and `impair`
warns with the rate netem will really produce. Bursty loss is a loss
model, `gemodel` or `state`, in tc's grammar.

```text
Change an endpoint's impairment at runtime: `impair r1:eth0 delay 50ms loss 1%`, `--dir in|both` for what it receives, `--clear`, `--partition`/`--heal`; or a network's between two nodes with `--pair SRC DST`. `--show` lists what every endpoint has.

The impairment replaces the endpoint's whole netem and is kept in the lab's state, so `apply`, `verify` and `snapshot` see it.

JSON OUTPUT (with `--show --json`): { "schema_version": 1, "lab": str, "endpoints": { "NODE:IFACE": { ... } | null } } Schema: docs/json-schemas/impair-show.schema.json

Usage: nlink-lab impair [OPTIONS] [ENDPOINT] [SPEC]...

Arguments:
  [ENDPOINT]
          The endpoint (`node:iface`). Not with --show or --pair (whose impairment starts right after it)

  [SPEC]...
          The impairment: `delay 50ms jitter 5ms loss 1% rate 10mbit` (`delay=50ms,loss=1%` too). Properties: delay, jitter, loss (a rate, or a loss model `gemodel P [R [1-H [1-K]]]` / `state P13 …`), rate, corrupt, reorder, duplicate, delay-correlation, loss-correlation, limit, seed (in place of the one the lab's seed derives). It replaces the whole impairment

Options:
  -L, --lab <LAB>
          The lab. Default: `$NLINK_LAB`, then the one `nlink-lab use` selected, then the only running lab

      --dir <DIR>
          Which way: `out` (what the endpoint sends), `in` (what it receives: installed on its link's other end), `both`

          Possible values:
          - out:  What the endpoint sends
          - in:   What it receives (the egress of its link's other end)
          - both: Both
          
          [default: out]

      --show
          Every endpoint's root qdisc, one line each: netem's delay, jitter, loss and rate, and whether it is partitioned (read over netlink)

      --clear
          Remove the impairment (in `--dir`)

      --partition
          Cut the endpoint off: drop everything it sends and receives, as a black hole (its own stack sees the sends succeed, so its TCP backs off and waits, as when a WAN goes dark). Its qdiscs (netem, `qdisc` block, rate limit, per-pair matrix) stay

      --heal
          End a partition: traffic flows again, through what it had

      --pair <SRC> <DST>
          A network's impairment from SRC to DST (node names), instead of an endpoint's: `--pair a b delay 20ms`. With --clear, removes it

      --network <NETWORK>
          The network of --pair (default: the one both nodes are members of)

      --rate-cap <RATE_CAP>
          With --pair: an HTB rate cap on top of the netem (`10mbit`)

  -h, --help
          Print help (see a summary with '-h')
```
